MagickVoice Sentinel

How a call gets from a headset to a compliance flag

Sentinel captures both sides of a collections call on the agent's Windows desktop, ships them to a Go gateway, and turns them into a summary, a promise-to-pay and RBI compliance flags. These diagrams are the machinery in between — what builds, what runs, and who calls whom.

01 — SERVICE MAP

Who calls whom

Six moving parts. The gateway is the only thing the endpoint can reach — no AI keys, no database credentials and no object-store credentials exist on a collections agent's desktop. Two identities authenticate every ingest connection at once: the device certificate supplies tenant_id and device_id, the bearer token supplies user_uid and role, and a disagreement between them closes the socket with 4403.

02 — BUILD

How the .exe gets built

Two executables come out of one Cargo workspace, and a WiX v4 package wraps them into a per-machine x64 MSI for SCCM or Intune. The build runs on Windows only — WiX targets .NET, and the binaries must come from the MSVC toolchain rather than mingw, because EV signing and WER symbolication both expect MSVC PDBs. One command drives it: client/installer/build.ps1.

03 — ENDPOINT

Two processes, one pipe

Capture has to run in the interactive session — WASAPI has no audio in session 0. Device identity has to survive a shift change. Those are different lifetimes, so they are different processes. The service supervises the agent and relaunches it on a doubling backoff; a run that stays healthy for 120 s resets the ladder, so an agent that crashes after 55 s of work cannot inch its way back to a one-second retry loop.

04 — DETECTION

Deciding that a call is happening

There is no dialer integration to ask. The agent watches the softphone's audio session and the two audio streams, and runs the state machine below. The thresholds are the real ones from VadConfig::default(). Nothing is uploaded until speech is confirmed — an armed-but-silent session times out after 20 s and the buffer is discarded, which is what stops a dialer parked on hold music from producing an endless stream of empty calls.

Why silence, not a hang-up event. The softphone's audio session can stay active through a hold, a transfer and a wrap-up screen. Eight seconds of two-sided silence is the signal that survives all three. It costs eight seconds of tail audio on every call, which is the price of never truncating one.

05 — AUDIO PATH

From a WASAPI buffer to a 34-byte header

The two channels are captured separately and never mixed: everything downstream — per-speaker sentiment, "who said the threatening sentence", the conduct rules that only apply to the agent — depends on knowing which side spoke. That is also why there is no diarization step anywhere in the pipeline. The channels arrive separate and stay separate.

06 — PROTOCOL

The ingest protocol, and what happens when the network drops

WSS /v1/ingest carries JSON control frames and binary media records over one socket. The server acks a cumulative watermark per (call_id, channel) at least every 2 s or every 100 segments, and the client deletes a spool row only when it is covered by an ack. Reconnect replays from acked + 1 — so a dropped connection costs bandwidth, never audio.

An ack the server cannot honour is never sent. If the watermark write fails, the ack is suppressed — the client keeps the segments and replays them. The alternative, acking optimistically, deletes the only copy of audio that never landed.

07 — END TO END

One call, all the way through

Machine boot to compliance flag. Note where each of the two identities is established: the device enrolls once, at install, and its private key is generated non-exportably in CNG so it is never in a file or in process memory; the user signs in per shift through the system browser with PKCE, and the agent holds only a refresh token in DPAPI user scope.

08 — ISOLATION

One query, six answers

Tenant isolation is the database's job, not the handler's. The gateway connects as sentinel_app, a NOBYPASSRLS role, and sets three transaction-local settings from the verified token. A query that forgets its tenant filter returns nothing rather than another tenant's rows — and /v1/calls has no capability gate in the handler at all, because a gate there would be a second, weaker copy of a rule the database already enforces.

Three operations legitimately precede any tenant context — consuming an enrollment token, registering the device, resolving a client certificate back to a device. Rather than weakening the policies for them, migration 0005 exposes exactly those three as SECURITY DEFINER functions, so the tenant-crossing surface of the whole system is three greppable names.
